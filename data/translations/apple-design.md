# 苹果设计

## 初步反应

当该技能首次被无特定问题使用时，只需回答：

>我准备帮助你打造流畅、苹果风格的网页界面，我的知识来源于苹果WWDC设计讲座，并翻译成网络版。

在用户提问之前，不要提供任何其他信息。

苹果如何打造界面，不再像电脑，而是像你身体的延伸。这些知识来自苹果WWDC的设计讲座——主要是《设计流体界面》（WWDC 2018）——被提炼并转化为网页平台（CSS、指针事件、'requestAnimationFrame'、弹簧库如Motion/Framer Motion）。

贯穿始终：**当动作从当前屏幕上的数值开始，继承用户速度，向前投射动量，并且随时可抓取和反转时，界面感觉栩栩如生。** 弹簧是让这一切变得自然的工具，因为它们本质上可中断且能感知速度。

## 核心理念

> “当我们把界面与我们的思维和动作方式对齐时，会发生一些神奇的事情——它不再像电脑，而是感觉像是我们无缝延伸的存在。”

界面在表现得像物理世界一样时是流动的：物体即时响应，持续运动，携带动量，在边界处抵抗，并且可以在运动中途被重新定向。下面所有内容都是为了更接近那个目标。

苹果将设计定位为服务于四大人类需求：**安全/可预测性、理解、成就感和快乐。** 这里的每一条规则都服务于其中之一。

## 1.响应——终止延迟

一旦出现延迟，直接感就会“直接坠落”。回应是一切基础。

- **指针向下响应，而非松开。** 按下按钮即刻高亮。等“咔嗒”或补妆后才显示反馈感觉很死气沉沉。
- **对每一个延迟保持警惕。** 审计去弹、人工定时器、过渡等待以及~300毫秒的分流延迟。输入路径上任何非本质的部分都是回归。
- **反馈必须在*整个*交互过程中*持续，而非仅在结束时。**对于拖动、滑块或抽屉，请全程以1：1方式更新UI中的指针——切勿仅在手势完成时才进行动画。

```css
/* Feedback lives on the press, and it's instant */
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2.直接操作 — 1：1 跟踪

>“触摸与内容应当同步发展。”

当用户拖动某物时，它必须始终粘在手指上——并且要尊重*抓取位置*的偏移。抓取时瞬间切换到元素中心，幻觉立刻被打破。

- 使用带有“setPointerCapture”的指针事件，使跟踪即使指针离开元素边界时仍能继续。
- 跟踪一个简短的**速度/位置历史**（最近几次“指针移动”事件），而不仅仅是当前点——你需要释放时的速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // respect where they grabbed
  // ...track position + timestamp history for velocity
});
```

## 3.可中断性——最重要的原则

> “思想和动作是并行发生的。”

每个动画都必须随时可中断和重定向。用户必须能够在飞行中抓住移动元素并反向移动，无需等待动画结束。用户再次抓取的闭合模态应跟随手指方向——而不是先完成闭合再重新打开。

- **切换过程中切勿锁定输入。**
- **始终从*presentation*（当前）值开始动画，绝不要用目标值。** 中断时，读取元素的实时屏幕变换，然后从那里开始新动画。从逻辑/目标值开始会有明显的跳跃。
- **避免使用CSS过渡和“@keyframes”来处理任何手势驱动的动作**——它们无法在飞行中顺畅地抓取和反转。弹簧默认会从当前值开始动画，这正是中断所需要的。
- **当手势反转时，混合速度——不要硬切。** 在反转时用另一个动画替换一个动画会产生速度不连续，形成“砖墙”。通过重定向传递速度的弹簧库会避免使用。（这是iOS的*加法动画*原生功能;在网页端，选择一个从当前速度重新定位的弹簧库。）
- **将二维运动分解为独立的X和Y弹簧。** 当X和Y速度不同时，单一弹簧在二维距离上会不同步。

## 4.行为胜于动画——使用弹簧

> “把动画想象成你和物体之间的对话，而不是界面规定的东西。”

预设脚本、固定时长的动画无法响应新输入。弹簧可以——新的输入只是改变目标，运动保持连续。只要用户能触摸到，就用弹簧。

苹果有意用两个对设计师友好的参数替换了物理三元组（质量/刚度/阻尼）。想想这些：

- **阻尼比** — 控制超冲。“1.0” = 临界阻尼，无弹跳，平滑安定。“< 1.0” = 超冲和振荡。较低=弹跳。
- **响应** — 数值到达目标的速度，单位为秒。更低=更灵敏。**这不是“持续时间”**——弹簧没有固定的持续时间;其稳定时间来自参数。

**默认：**
- 大多数UI起始于**阻尼“1.0”**（关键阻尼）——优雅且不干扰。
- 仅在手势本身带有动量时（弹跳、投掷、拖拽释放）时才添加弹跳（**阻尼~'0.8'**）。菜单突然消失，感觉不对劲;你弹过的牌上超出了感觉。

**苹果发布的具体价值观：**

|互动 |阻尼 |回应 |
|--- |--- |--- |
|移动/重新定位（例如点画）|“1.0” |'0.4' |
|旋转 |'0.8' |'0.4' |
|抽屉 / 纸张 |'0.8' |'0.3' |

**Web 映射（Motion / Framer Motion）:** “bounce” + “duration” 弹簧 API 与苹果的阻尼 + 响应非常接近。安全屋的风格是“阻尼：默认全处弹簧1.0”;把弹跳留给动能驱动的身体互动。

```js
import { animate } from 'motion';

// Critically damped default (no overshoot)
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// Momentum interaction — a little bounce, only because a flick preceded it
animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });
```

## 5.速度切换——拖曳与动画之间的接缝

当手势结束时，动画必须**以手指的精确速度继续**，这样拖曳和动画之间没有明显的接缝。这正是区分“流体”和“细”的关键。

将指针的释放速度当作弹簧的初始速度。有些弹簧API要求**相对**速度——通过剩余距离进行归一化：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

示例：元素在'y=50'处，目标'y=150'（还有100像素），手指移动50像素/秒→初始弹簧速度='50 / 100 = 0.5'。Framer Motion / Motion 直接获取绝对 px/s 速度（“velocity”选项），所以通常你会直接给它原始值。

## 6.动量投射——动画化到手势*要去的地方*

>“从小输入产生大输出”。

不要从*释放点*跳到最近的边界。用速度**投影静止位置**——就像卷轴减速一样——然后吸附到最接近该投影点的目标。这正是让一部电影感觉像是“抛弃元素”的原因。

苹果的精确投影函数（摘自*设计流体界面*示例代码）：

```js
// decelerationRate ≈ 0.998 for normal scroll feel; 0.99 for snappier
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);   // choose target from the projection
animateSpringTo(target, { velocity: releaseVelocity }); // then hand off velocity (§5)
```

注意：物理教材中的“v²/（2·decel）”并非苹果官方发布的格式——请使用上述指数衰减形式。这是良好底板和旋转木马的标准行为（Vaul， Embla）。

## 7.空间一致性——对称路径，锚定原点

> “如果某物以某种方式消失，我们期望它从来处出现。”

- **进入和退出沿同一路径。**从右侧滑入的面板必须向右关闭。从右到上/从下而上感觉脱节且令人困惑。
- **将交互锚定在其源节点。** 菜单、弹出或表格应由触发元素发出——将“transform-origin”设置为触发器，这样按钮与内容之间的空间关系就很明显了。（这与弹出物从触发点而非中心尺度是相同的起源意识点。）
- **对可逆跃迁镜像放宽**，使出站路径与返回路径匹配（两个方向使用逆立方-贝塞尔控制点）。

## 8.暗示动作方向

人类通过轨迹预测最终状态。中间运动应该能预示事情的发展方向——控制中心模块“向你的手指方向生长并扩展”。让中间帧指向结果，而不是盲目插值。

## 9.橡皮筋——软边界

在边缘时，逐渐抵抗，而不是硬着头皮停下。硬停止显示为“冻死”;持续抵抗读起来是“响应迅速，但除此之外没有更多内容”。应用阻尼效果，阻尼随着用户拖越越远越越大。

```js
// The further past the bound, the less the element follows — real things slow before they stop
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10.手势设计细节（“感觉”清单）

- **Tap：** 在触地*下*时高亮（即时），在上按时提交。在目标周围添加约10px的滞后/击中填充，并允许通过拖拽取消再拖回。
- **拖动/滑动：** 需要一个小的移动阈值（滞后，~10px）才能确定方向，然后按1：1跟踪。
- **从第一步开始并行检测所有合理的手势**，一旦意图明确，便自信地取消失败者。避免只报告*最终*状态（类似“向左滑动”事件）的识别器——它们会丢弃你所需的持续反馈追踪。
- **最小化消歧隔延迟。** 双重分断检测不可避免地延迟单分点;只有在真正存在双击的地方才支付这个成本。

## 11.帧级平滑度

流畅度是关于*帧数*，而不仅仅是帧率。

- 将每帧位置变化保持在感知阈值以下，以避免闪烁。
- 对于非常快的运动，细微的**运动模糊/拉伸**编码速度，比硬锐的划线更易读取。
- “requestAnimationFrame”是网页上的显示同步时钟（苹果使用“CADisplayLink”）。只制作适合合成器的属性——“变换”和“不透明度”——并在即将发生运动时用“will-change”来提示。

## 12.材质与深度——半透明传递层级关系

苹果使用半透明材料作为漂浮的功能层，带来结构感而不抢走焦点。在网上，可以用“背景滤镜”来近似。

- **将导航/工具栏/表格构建为半透明图层**（“背景滤镜：模糊（）” + 半透明背景），内容在下方滚动——而不是占据固定条带的不透明条。
- **材料重量编码层级结构：**较深/较重的材料分隔结构区域（侧栏）;较轻的材料则能突出互动元素（按钮）。**绝不要把轻质半透明表面叠加**——可读性会崩溃。
- **较大的表面应被解读为更厚：**模糊更强+阴影更深，比小缺口更深。考虑上下文感知阴影——在繁忙或文字内容上用较重的效果以实现分离，在纯色背景上用较浅的阴影。
- **调暗以对焦，分离以保持流畅。**模态任务将表面与调光幕布配对，并将背景推回/向下。平行、无遮挡的面板利用半透明和偏移，*没有*纱网，这样流动不会被打断。对于叠层图纸，逐步调暗并推回每层母图层。
- **鲜艳度使文字在背景变化中保持清晰可读。** 在模糊/半透明表面上，不要使用平面灰色文字——使用更高对比度、稍重的字重，并加一个小的字距凸起。把颜色涂在实心图层上，而不是半透明的前景。
- **滚动边缘效果，而非硬分隔线。** 不要在粘性标题下方用1像素边框，而是在内容与浮动chrome交汇处淡出一个小的模糊/渐变蒙罩——仅在浮动界面与内容重叠的地方。
- **实体化，不要只是淡出。**对于玻璃/模糊表面，动画化模糊半径并在进入/退出时一起放大，这样表面看起来像是真实的材质到来，而不是单纯的不透明度淡化。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* bright top edge = light catching the material */
}
```

## 13.多模态反馈——运动 + 声音 + 触觉

三条感官结合规则（摘自*设计音频-触觉体验*）：

1. **因果关系**——反馈的成因必须显而易见。在实际因果事件（切换开关翻转、物品卡回归）时触发它，并让它的角色与动作的物理性相匹配。
2. **和谐**——视觉、声音和触觉必须在同一帧上**同时激活。它们之间的延迟破坏了幻觉。不要让CSS的过渡延迟到音频/触觉（振动API）的延迟。
3. **效用性**——只在值得用处添加反馈。把触觉/声音留给有意义的时刻（成功、失误、提交、响指）。过度反馈会让用户忽视所有这些。

## 14.减少运动和可达性

减少运动并不意味着*没有*反馈——而是更温和、非前庭的等效物。响应三个独立信号，并将其整合到组件中：

- **'偏好减少运动：减少'** — 用短不透明度替代滑片/弹簧/视差**交叉淡入淡出或静态过渡**。减少弹性/超冲。保持不透明度和颜色变化，帮助理解。
- **'偏好降低透明度：减少'** — 让半透明表面更结霜/更坚实：提高背景透明度，去除模糊。
- **'偏好对比度：更多'** — 近实心背景，带有明确对比的边界。

另外：避免全视角移动的背景、缓慢的循环振荡（接近0.2 Hz/每5秒一个周期），以及突然的亮度跳跃（方便切换暗↔光主题）。让大型移动物体在移动时半透明，大面积表面在大范围重新定位时渐隐，稳定后又恢复。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15.排版——光学尺寸、追踪、前置

苹果设计字型会随着大小变化;网络上同样适用同样的纪律。（摘自《界面排版细节》，WWDC 2020。）

- **跟踪（字距）是特定大小的——绝不会对所有尺寸都用一个值。** 大显示文本需要*负*跟踪（字母随着增长而读得过远）;小字需要稍微*正向*的追踪以保证可读性。固定的“字母间距”在某些地方是错误的。收紧航向，保持船体接近“0”。
- **前导（线高）轨道尺寸反比。** 大标题时紧，正文较宽松。对于带有高升/降行符的文字，可以提高它;把界面收紧，让界面内容密集、信息量大。
- **从权重+尺寸+前导作为一组构建层级，**而非仅仅是大小。用重量来强调——它能增加存在感，同时不占用更多空间。
- **尊重用户的文本大小设置**（动态类型）。用*与*文本一起进行比例布局——用“rem”/'em'的间距，而不是固定的px——这样大字体不会破坏布局。
- **默认使用平台系统字体**，然后是自定义字体;它已经提供光学尺寸、追踪表和可读性调校功能。只有有理由才会覆盖。

```css
:root { font: 100%/1.5 system-ui, sans-serif; } /* body: system font, comfortable leading */

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* tight leading for large text */
  letter-spacing: -0.02em;  /* negative tracking as it grows */
  font-optical-sizing: auto;
}
```

## 16.设计基础——八大原则

上述动作和工艺体现了苹果的八大设计原则（*伟大设计原则*，WWDC 2026）。用这些名字来推理：

1. **目的。** 有意图地制作;决定哪些*不*建造。每个功能都需要用户投入时间、注意力和信任——只在值得的地方投入预算。
2. **主动性。** 让人们掌控：提供选择，不强迫单一路径。用宽恕来支持——失误很容易撤销，只有真正破坏性、不可逆转的行为才会有确认对话（请节制使用;过度使用会让人点击）。
3. **责任。** 以用户利益为先。隐私：在合适的时机提出，只针对需要的部分，透明透明。安全性：预料滥用和有害——尤其是AI应用（过敏敏感的食谱应用不得建议有害成分）。添加预览、确认和免责声明;删减风险大于其价值的特征。
4. **熟悉感。** 建立在人们已知的基础上。使用既不过于字面化也不过于抽象的隐喻（垃圾桶意味着删除），并尊重它们的物理性。保持一致性：看起来一样的东西必须行为一致，并且存在于同一个位置（在macOS上，“接近”总是在左上角），这样人们才能预测接下来会发生什么。只有在你能证明熟悉的模式更好时才打破它——然后测试它，不要假设。
5. **灵活性。**针对不同情境、设备和全方位能力进行设计。适应平台（iPhone = 快速触控;桌面 = 深度工作流程，指针控制精准）和情境。设计包容性（年龄、语言、专业能力、可及性）。当没有单一布局适合所有人时，让玩家个性化——重新排列控件，隐藏不使用的内容。
6. **简洁——而非极简主义。** 去除不必要的部分，使核心目的更加突出;把所有东西埋在一个地方看起来很简洁，但并不简单。要简洁（语言简单，无行话，步骤更少）和清晰（使用层级——顺序、间距、对比——让最重要的内容最明显）。每个元素都有其位置;有时候*添加*上下文会更简单（比如用视频清理器显示剩余时间）。先展示共同路径，再深入一层的高级选项。
7. **工艺。** 对细节的毫不妥协关注能建立信任。精美的排版、适应明暗的色彩、清晰的图标设计，以及能提供即时自然反馈的响应动画。没有什么是随机的——每一个间距、时机和对齐数值都是你可以为自己辩护的刻意选择。抖动的滚动、错位的图标和旋转时断裂的布局，都显得粗心大意。工艺需要不断迭代和耐用性——随着功能和硬件的变化，设计也要不断进化。
8. **喜悦。** 是因为其他七条都做对了，而不是在上面加了彩纸屑。决定你希望别人感受到的情绪（平静、自信、兴奋），并在每一个决定中强化它。

适用于以下情况的战术规则：

- **反馈有四种类型：**状态、完成、警告、错误。确认有意义的操作，公开持续状态，问题发生前警告，在线验证（非提交时）。
- **寻路。** 每个屏幕都应该回答：我在哪里？我能去哪儿？那里有什么？我怎么出去？永远不要困住使用者。
- **分组与映射。** 邻近性意味着关系;在它影响的区域附近放置一个控制点，并设置控制点以反映它们的变化。如果你需要标签来解释控制，那映射就很薄弱。
- **直接、具体的标签胜过安全的通用标签。** 导航项目应以内容命名（“进展”、“图书馆”），而非模糊的伞形名称（“首页”）。具体性带来可预测性。

## 17.流程

- **原型互动式——一个互动演示价值“百万个静态设计”。** 你通过建造和玩弄界面来发现它;一个可运行的原型还为最终实现的平庸设定了坚实的门槛。
- **将交互与视觉结合设计。** “你不应该分辨哪里结束，哪里开始。”运动不是像素之后添加的图层。
- **在真实情境下与真实人物测试**，并以新鲜的视角审视动作——慢动作/逐帧播放，捕捉全速看不见的部分。
